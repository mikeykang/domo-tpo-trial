# 작업 지시서 · platform/index.html 개정

오너(한국 화장품 브랜드의 일본 진출 프로젝트 DOMO)가 2026-08-13에 두 가지를 지시했다.
이 저장소는 `mikeykang/domo-tpo-trial`, GitHub Pages로 `https://mikeykang.github.io/domo-tpo-trial/` 에 서빙되는 한국어 리서치 사이트다.
대상 파일은 `platform/index.html` 하나이고, 루트 `index.html`의 카드 한 줄도 소폭 수정이 필요하다.

## 지시 1 · API 관련 내용 전부 제거

`<h2 id="tech">API가 주는 것과 안 주는 것</h2>` 섹션에서 **API/엔드포인트/연동 기술 내용만** 걷어낸다.

**지운다:**
- `<h3>큐텐 QSM API · 실측 결과</h3>` 이하 전부. POST 엔드포인트 `<pre>` 블록, 9클래스 30메서드 목록,
  「분석용 READ API가 존재하지 않는다」 `.cal` 박스, 「연동 자체는 쉽다」 문단, 인증키·ErrorCode·갱신주기 gotcha.
- `<h3>우리가 직접 확인한 프론트엔드 표면</h3>` 이하 전부. `SearchResultAjaxTemplate.aspx` / `GoodsReviewAjaxAppend.aspx` `<pre>` 블록 포함.
- `<h3>아마존 SP-API · 일본 마켓플레이스</h3>` 이하 전부. marketplaceId·엔드포인트 `<pre>` 블록, 레이트리밋, Listings Items, SQP·Data Kiosk `.cal` 박스.
- 데이터 열람 비교표(「내 매출·주문 / 상품별 PV·CVR / 플랫폼 전체 검색어 랭킹 …」 표). API 열람 방식을 나열하는 표라 통째로 제거.
- 「우리가 모르는 것 > 지금 확인해야 할 것」 목록의 `getDefinitionsProductType` 항목(7번).
- 상단 목차 `.toc`의 `<a href="#tech">API가 주는 것</a>`.

**지우면 안 되는 것 (같은 섹션 안에 섞여 있다):**
- `<h3>물류</h3>` 이하 전부. TracX Logis(구 Qxpress) 사명 변경, 큐텐 공식 물류 파트너 9곳 중 5곳이 한국계,
  배송 단가 비교표, ネコポス 관련 `.note` 박스. 이건 API가 아니라 물류다.
- 「큐텐에는 Nint급 서드파티 인텔리전스가 아예 없다」 `.cal` 박스의 **시장 사실**은 살린다.
  다만 API 프레이밍을 걷어내고 「경쟁 인텔리전스를 어디서도 살 수 없다」는 취지로 다시 쓴다.
  (Nint가 라쿠텐·아마존·야후 3몰만 커버하고 큐텐을 지원하지 않는다는 사실. `qoo10-tech.md` 4-3 참조)

남는 내용에 맞게 `<h2>` 제목과 `id`를 바꾼다(예: `id="logi"` 「물류와 경쟁 정보」). 목차와 본문 앵커를 함께 고친다.
루트 `index.html`의 platform 카드 `.k` 줄에 있는 「API 실측 30메서드」 문구도 다른 것으로 교체한다.
문서 하단 `.foot`의 8개 조사 레인 설명은 사실 기술이므로 그대로 둔다.

## 지시 2 · 모든 섹션에 출처를 달고, 출처 신뢰도와 본문-출처 일치를 검증

현재 문서는 수치는 많은데 출처 각주가 거의 없다. 오너의 지적이다.

### 근거 자료
같은 디렉터리 `platform/_sources/*.md` 에 2026-08-13 조사 8건의 원본 보고서가 있다(README.md에 레인 설명).
**본문의 모든 수치는 이 8개 파일에서 나왔다.** 각 파일은 주장마다 `[출처: URL, 날짜]` 와
신뢰도(`확실` / `추정` / `불확실` / `소문`)를 달고 있고, 끝에 「모순 / 미확인」 절이 있다.

### 해야 할 일
1. **본문의 모든 사실 주장을 `_sources/` 에서 찾아 대조한다.** 숫자, 날짜, 요율, 제도명, 인용문 전부.
2. **일치하지 않으면 본문을 고친다.** 소스보다 강하게 단정한 곳은 약하게 바꾸고,
   소스에 없는 주장은 지운다. 소스가 `추정`인데 본문이 단정형이면 `추정`으로 낮춘다.
3. **출처를 단다.** 섹션마다, 그리고 모든 표 아래에 출처를 명시한다.
   - 이미 CSS에 `.src` 클래스가 있다(11px 모노, subtle). 표 바로 아래 `<p class="src">` 로 붙인다.
   - 링크는 실제 URL로 걸되 `<a href="...">` 텍스트는 발행처 이름으로 짧게 (예: `Qoo10大学` `재무성` `MIPRO` `sell.amazon.co.jp`).
   - 발행처 + 날짜를 반드시 같이 적는다. 날짜가 없으면 「날짜 미상」이라고 쓴다.
   - 이미 문서에 있는 `.tag` 클래스(`ok`/`mid`/`low`)로 신뢰도 배지를 붙일 수 있다.
4. **신뢰도 위계를 지킨다.** 정부·플랫폼 공식 문서 > 대형 로펌·업계지 > 컨설팅/대행사 자료 > 개별 블로그·일화.
   **컨설팅 블로그 하나에 근거한 주장에 `확실` 배지를 달면 안 된다.**
   한국 대행사 블로그들이 같은 문구를 복제하는 경우가 많으니(`seller-field.md` 함정 7 참조) 단일 출처 확산을 의심한다.
5. **가장 결정적인 주장 12~18개는 원 URL을 직접 열어서(WebFetch) 확인한다.** 우선순위:
   - 아마존 판매수수료 2026-04-01 +0.4%p (뷰티 8.4% / 10.4%) → `sell.amazon.co.jp/pricing`
   - FBA 배송대행 요율표 (標準2b ¥415 등) → 같은 페이지
   - 큐텐 뷰티 판매수수료 10% + 해외 +2% → `university.qoo10.jp/cost/`
   - 메가와리 20% 쿠폰의 셀러 10% / 큐텐 10% 분담 → `article-university.qoo10.jp/entry/152`
   - Q랭킹 2축 산식 → `article-university.qoo10.jp/entry/17`
   - 메가와리 참가 요건(직전 3개월 주문 이력, 취소율 10%)
   - 큐텐 2025년도 유통총액 3,000억엔 + 투명화법 지정 2026-06-12
   - 개인수입 24개 룰 → 후생노동성
   - 「해외 사이트의 대일 판매는 개인수입에 해당하므로 허가 불요」 MIPRO 인용문
   - 2028-04-01 소비세 신설 + 물품 플랫폼 과세 → 재무성 令和8년도 대강 / AMT·長島 뉴스레터
   - 0.6掛け 특례 폐지 (이르면 2026-04-01)
   - HS 3304/3305 WTO 협정세율 무세 → 세관 실행관세율표
   - 일본 상표(JPO) 요건 + 출원번호만으로 브랜드 등록 신청 가능
   - 화장품 효능 56항목 및 美白·주름개선의 의약부외품 이관
   - 일본 화장품 EC화율 8.82% → METI (2024년 데이터, 2025-08-26 공표)
   - 메가데뷔 188개 브랜드 누적 35억엔 / 51개(25%)만 분기 1,000만엔 돌파
   **열어봤는데 내용이 다르면 본문을 소스에 맞춘다. 페이지가 죽었거나 로그인 벽이면 그 사실을 각주에 적는다.**
6. **검증 결과를 「우리가 모르는 것」 섹션에 반영한다.** 확인 실패한 출처, 본문과 어긋나서 고친 항목을 추가한다.

## 지키는 것

- **디자인을 바꾸지 않는다.** 파일 상단 `<style>` 블록이 이 사이트의 공통 디자인 시스템이다. 새 클래스가 꼭 필요하면 기존 톤 안에서 최소한으로.
- **em dash(—)를 쓰지 않는다.** 오너의 표준 규칙이다. `·` 나 마침표로 대체한다.
- **일본어를 그냥 두지 않는다.** 모든 일본어 용어에 한국어 뜻을 병기한다. 법령·제도명은 원문을 남기되 괄호로 뜻을 단다.
- **없는 것을 지어내지 않는다.** 확인 못 한 항목은 공란으로 두고 그렇게 적는다.
  본문에 이미 「한국 → 일본 배송 단가는 요금표를 못 구해 추정치를 채우지 않았다」고 밝힌 대목이 있다. 이 태도를 유지한다.
- **새 사실을 추가하지 않는다.** 이 작업은 제거와 검증이지 확장이 아니다. `_sources/` 에 없는 내용을 새로 조사해 넣지 않는다.
  (단 5번의 원문 확인 과정에서 본문이 틀렸음을 발견하면 고치는 것은 당연히 포함된다.)

## 마무리

1. 수정 후 HTML 구조를 검증한다. 표의 `<th>` 개수와 각 행 `<td>` 개수(colspan 반영)가 맞는지, 앵커가 다 살아있는지.
2. 커밋하고 푸시한다. **이 저장소는 여러 세션이 동시에 푸시한다.** 반드시 `git fetch` → `git rebase origin/main` → `git push` 를
   실패 시 재시도하는 루프로 올린다. 충돌이 나면 `git rebase --abort` 하고 무슨 일이 있었는지 보고한다.
3. 커밋 메시지는 영어 소문자 한 줄 제목 + 빈 줄 + 본문 몇 줄. 이 저장소의 기존 커밋 스타일을 `git log` 로 보고 맞춘다.
4. GitHub Pages 빌드는 8분 안팎 걸린다. 푸시 후 `gh api repos/mikeykang/domo-tpo-trial/pages/builds/latest` 로 상태를 확인하고,
   `built` 가 되면 `https://mikeykang.github.io/domo-tpo-trial/platform/` 를 열어 렌더링을 확인한다.
5. 마지막에 한국어로 보고한다: 무엇을 지웠는지, 출처를 몇 개 달았는지,
   **원문 대조에서 본문이 틀려서 고친 항목이 무엇인지**, 확인 못 한 것이 무엇인지. 불릿으로 짧게.
